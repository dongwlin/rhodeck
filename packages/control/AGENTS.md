# Control 维护指南

## 运行与状态所有权

- 运行驱动、worker 观察、停止和持久化共享同一 `Run` 状态所有者；不要让 adapter、存储机制或调用端另行维护运行结论。业务状态与 cleanup 分开更新，晚到的清理故障保留已确认事实。
- 调用方计划与编译后的 Core 参数分别持有：记录保存原始计划，worker 接收编译参数。准备结果、快照和传给扩展接口的数据保持独立副本，不能让外部修改影响已准入运行。
- 运行 context 的取消只触发停止流程；已可能发送的命令使用独立、有界的 context。停止确认与进程关闭分别计时；`Runtime.Close` 的等待被取消后，共享清理仍继续，目录所有权保留至清理结束。
- Core task ID 仅在本次 worker 内关联到调用方 task ID；批次完成须校验完整的任务集合及各自链路结论。相同类型的任务不能按类型或回调到达顺序猜测归属。

## 适配器扩展

- 具体任务的严格输入编译与 reducer 留在各 `adapters/` 包；注册表由调用方显式提供。`Prepare` 必须确定、无文件/原生/设备副作用，允许并发调用，并为每个有解释目标的任务创建独立 reducer。
- `objective_policy` 由具体准备输入选择；`none` 不返回 targets 或 reducer，不能伪造 typed 结果。共同的目标校验、事实合并和聚合规则由 control 持有，不在各 adapter 重复实现。
- reducer 在单一观察循环中、结果锁外接收独立回调数据；自身临时状态也须有界。只返回声明目标的过滤事实；相同事实可重复，不同事实不得覆盖已确认值，summary 同样不可变。
- 无关联回调不能产生目标事实。`UnassociatedObservationClassifier` 只允许精确识别显式 `taskid=0` 的非事实进度，不能放宽执行回调的关联条件或改变 reducer 的执行范围。

## 记录与恢复

- 保持副作用与落盘顺序：准入记录先于 worker 启动，安装元数据先于设备连接；确认的任务事实及时保存，typed 事实先保存再发布 typed 事件。快照与写入必须一起串行化，避免旧快照覆盖新事实。
- `internal/recordfs` 仅负责目录锁、有界文件操作与原子替换；记录校验、版本和中断恢复规则留在 control。持久化失败保留 `ErrRecordWrite` 身份；typed 保存失败时不发布尚未落盘的事件，终态仍保留已观察的内存事实。
- 恢复不调用 adapter 准备、不启动 worker；保留已确认事实，将未确认状态标为中断未知。损坏或不兼容记录拒绝打开，不删除证据。目录锁只证明同一 data-dir 的所有权，不能扩大为设备互斥或动作已停止。

## 测试选择

- 生命周期、停止和目录所有权使用真实 helper 子进程，覆盖共享关闭、取消等待后仍持锁、慢消费者和进程回收；不要只断言状态值。
- adapter 输入与 reducer 规则在所属包验证；关联、目标聚合、事件预算与持久化顺序在 control 层验证。相关用例包含同类型多任务、重复/冲突事实、缺失关联和输入策略分支。
- 记录变更覆盖往返与独立副本、坏记录拒绝、中断恢复和保存失败；文件替换机制与业务恢复分层验证。跨平台原子替换测试不能作为断电持久性证明。
